# Список G‑кода для 3D‑печати (Marlin / Klipper)

> Команды расположены от наиболее часто встречающихся в управляющем коде (слайсерный вывод, стартовый G-код) к более редким.

---

## 1. G0 / G1 — линейное перемещение

**Описание:** перемещение осей в заданную точку с заданной скоростью.  
G0 формально означает «холостой ход», G1 — «рабочий ход». В 3D-печати оба варианта выполняют одно и то же движение, G1 используется для экструзионных перемещений.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X` `Y` `Z` | абсолютные координаты назначения (мм). Ось, не указанная в команде, сохраняет текущее положение. |
| `E` | длина выдавливаемого пластика (мм). Положительное значение — выдавить, отрицательное — втянуть. |
| `F` | скорость подачи (мм/мин). Действует для данной команды и всех последующих, пока не будет изменена. |

**Пример:**
```
G1 X100 Y50 Z0.3 E0.5 F1500   ; переместиться в X100 Y50 Z0.3, выдавить 0.5 мм, скорость 1500 мм/мин
```

**Различия прошивок:** команды полностью идентичны.

## 2. G92 — установка текущей позиции

**Описание:** задаёт текущее положение осей без физического перемещения. Чаще всего применяется для сброса координаты экструдера (`G92 E0`) после ретракта или перед началом нового слоя.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X` `Y` `Z` `E` | новое виртуальное значение для соответствующей оси. Отсутствующая ось не изменяется. |

**Пример:**
```
G92 E0      ; обнулить позицию экструдера
G92 X0 Y0   ; считать текущие X, Y равными нулю (виртуальный сдвиг)
```

**Различия прошивок:** синтаксис и поведение совпадают.

## 3. M104 — нагрев сопла (без ожидания)

**Описание:** запускает нагрев горячего конца до заданной температуры и немедленно продолжает выполнение кода.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `S<темп>` | целевая температура в °C. |
| `T<индекс>` | номер экструдера (по умолчанию 0). |

**Пример:**
```
M104 S210 T0   ; начать нагрев первого сопла до 210 °C
```

**Различия прошивок:** нет.

---

## 4. M109 — нагрев сопла (с ожиданием)

**Описание:** включает нагрев и приостанавливает выполнение до достижения заданной температуры.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `S<темп>` | ждать, пока температура **достигнет и стабилизируется** на указанном значении. |
| `R<темп>` | ждать, пока температура **достигнет** указанного значения (без стабилизации). Используется, чтобы разрешить продолжение уже при частичном нагреве. |
| `T<индекс>` | номер экструдера (по умолчанию 0). |

**Пример:**
```
M109 S210      ; нагреть до 210 °C и ждать стабилизации
M109 R150 T1   ; ждать, пока второй экструдер нагреется до 150 °C
```

**Различия прошивок:** Marlin и Klipper поддерживают оба параметра `S` и `R` одинаково.

## 7. G28 — парковка (хоминг)

**Описание:** перемещает оси в начальное (известное) положение, используя концевые датчики.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X` `Y` `Z` | указание оси для хоминга; если ни одной не задано — хоминг всех трёх. |
| **Marlin-only:** `O` | подавляет автоматическое отключение выравнивания стола после хоминга. |
| `L` | восстанавливает состояние выравнивания стола после хоминга. |
| `R` | хоминг по «сырым» координатам. |

**Пример:**
```
G28            ; хоминг всех осей
G28 X Y        ; хоминг только X и Y
```

**Различия прошивок:**
- **Marlin:** поддерживает дополнительные флаги `O`, `L`, `R`, варианты парковки с датчиком.
- **Klipper:** G28 может задавать оси X, Y, Z, но не использует флаги Marlin. Поведение определяется конфигурацией `[stepper]` и `[homing]`. Выравнивание стола (bed mesh) после G28 по умолчанию может отключаться — это настраивается.

## 8. G90 / G91 — абсолютное / относительное позиционирование

**Описание:** переключает режим интерпретации координат X, Y, Z.

- **G90** — абсолютный режим (координаты задаются от машинного нуля).
- **G91** — относительный режим (координаты задаются от текущего положения).

**Аргументы:** нет.

**Пример:**
```
G90            ; перейти в абсолютный режим
G91            ; перейти в относительный режим
```

**Различия прошивок:** команды идентичны.

---

## 9. M82 / M83 — абсолютный / относительный режим экструдера

**Описание:** управляет интерпретацией координаты E.

- **M82** — абсолютный режим экструдера (E — абсолютная позиция от старта печати).
- **M83** — относительный режим экструдера (E — приращение).

**Аргументы:** нет.

**Пример:**
```
M82            ; абсолютный режим экструдера
G1 E5          ; переместить экструдер в абсолютную позицию 5 мм
M83            ; относительный режим экструдера
G1 E5          ; выдавить ещё 5 мм
```

**Различия прошивок:** команды идентичны.

## 10. M106 / M107 — вентилятор обдува модели

**Описание:** управление скоростью вентилятора охлаждения детали.

- **M106** — включить / установить скорость.
- **M107** — выключить (эквивалентно `M106 S0`).

**Аргументы для M106:**

| Аргумент | Значение |
|----------|----------|
| `S<скорость>` | скорость вентилятора. <br>**Marlin:** 0–255 (целое число, PWM). <br>**Klipper:** по умолчанию `0.0`–`1.0` (дробное число), но может принимать 0–255, если вентилятор настроен как обычный PWM-вентилятор (`[fan]` с `max_power: 1.0`). |
| `P<индекс>` | номер вентилятора (Marlin), в Klipper обычно один вентилятор обдува. |
| `I` `F` (Marlin) | доп. параметры для управления плавным изменением. |

**Пример:**
```
M106 S128       ; Marlin: 50% скорости, Klipper: 0.5 = 50%
M106 S0.5       ; Klipper: 50% скорости (не будет работать в Marlin)
M107            ; выключить вентилятор
```

**Различия прошивок:**
- **Marlin:** ожидает целое число 0–255.
- **Klipper:** основной синтаксис — число 0.0–1.0. Если конфиг вентилятора допускает `max_power: 1.0`, то также понимает 0–255.

## 11. M84 — отключение двигателей

**Описание:** отключает удержание шаговых двигателей (оси становятся свободными). Может использоваться с таймером автоматического отключения.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `S<сек>` | время бездействия в секундах, после которого двигатели отключатся автоматически. |
| `X` `Y` `Z` `E` | немедленно отключить указанные оси (если не заданы — отключаются все). |

**Пример:**
```
M84            ; немедленно отключить все двигатели
M84 S60        ; отключить двигатели после 60 секунд простоя
M84 X Y E      ; отключить только X, Y и экструдер
```

**Различия прошивок:** синтаксис одинаков.

## 13. G29 — автоматическая калибровка стола

**Описание:** запускает процедуру выравнивания (по датчику или вручную). Широко используется в стартовом коде.

**Аргументы (Marlin — сильно варьируются):**

- Без аргументов — автоуровень по определённым точкам.
- `P<тип>` — тип выравнивания.
- `A`, `B`, `C`, ... — настройки сетки.
- `Q`, `T`, `V` — опции тестирования/визуализации.

**Klipper:** G29 может вызывать калибровку сетки (`bed_mesh`), если сконфигурировано. Чаще используют макрос `BED_MESH_CALIBRATE`.

**Пример:**
```
G29            ; запуск автокалибровки стола
```

**Различия прошивок:**
- **Marlin:** огромный набор параметров, поведение зависит от типа датчика и конфигурации.
- **Klipper:** G29 обычно запускает `BED_MESH_CALIBRATE` без параметров. Для тонкой настройки применяют макрос `BED_MESH_CALIBRATE` с аргументами `PROBE_COUNT` и т.п. В Klipper предпочтительнее использовать макросы, а не G29.

## 17. T0 / T1 / … — выбор инструмента

**Описание:** выбирает активный экструдер (в многоматериальных системах).

**Аргументы:** номер инструмента (0,1,…).

**Пример:**
```
T0             ; активировать первый экструдер
T1             ; переключиться на второй
```

**Различия прошивок:**
- **Marlin:** встроенная команда, может выполнять смену с парковкой.
- **Klipper:** T0 и T1 работают, но обычно для сложной смены инструмента используют макрос `ACTIVATE_EXTRUDER` и настраиваемые процедуры.

| Аргумент | Значение |
|----------|----------|

| `T<индекс>` | номер экструдера. |
| `L<длина>` | длина выгрузки. |

**Пример:**
```
M600           ; запуск смены пластика с параметрами по умолчанию

**Различия прошивок:**
- **Marlin:** команда реализована в прошивке.
- **Klipper:** M600 не является встроенной командой; необходимо создать макрос `[gcode_macro M600]`, описывающий нужную последовательность.

## 24. M205 — настройки рывка (jerk)

**Описание:** устанавливает мгновенное изменение скорости (рывок).

**Аргументы (Marlin):**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y`, `Z`, `E` | рывок в мм/с. |
| **Klipper:** использует параметр `S` для «square corner velocity» (мм/с), а не классический рывок. |

**Пример:**
```
M205 X10 Y10 Z0.4 E5    ; Marlin: установить рывок
M205 S5                 ; Klipper: установить square corner velocity 5 мм/с
```

**Различия прошивок:**
- **Marlin:** управляет рывками по осям.
- **Klipper:** не использует оси X/Y/Z/E для рывка; вместо этого M205 S… задаёт лимит угловой скорости. Для управления остальными лимитами применяется `SET_VELOCITY_LIMIT`.

## 25. M420 — восстановление и настройка сетки выравнивания стола

**Описание:** загружает сохранённую сетку выравнивания (bed leveling mesh) и управляет её применением. Часто используется в стартовом G-коде для активации уже известной сетки без повторного пробинга.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `S<0/1>` | 0 – отключить использование сетки; 1 – включить (загрузить из EEPROM). |
| `Z<высота>` | высота, на которой плавно отключается коррекция (fade height), мм. |
| `L<индекс>` | номер сетки, если сохранено несколько (Marlin). |
| `V` | (Marlin) вывести информацию о состоянии сетки (verbose). |

**Пример:**
```
M420 S1        ; включить использование сохранённой сетки
M420 S1 Z5     ; включить сетку с fade height = 5 мм
M420 V         ; показать состояние сетки
```

**Различия прошивок:**
- **Marlin:** полная поддержка аргументов S, Z, L, V.
- **Klipper:** M420 не является встроенной командой; для управления картой стола применяют `BED_MESH_PROFILE LOAD=...` или `SET_BED_MESH`. Часто создают макрос `M420 S1`, вызывающий `BED_MESH_PROFILE LOAD=default`.

## 28. M502 — сброс на «заводские» настройки

**Описание:** возвращает все параметры к значениям, жёстко прописанным в прошивке (Configuration.h), без сохранения в EEPROM. Для окончательного сброса обычно выполняется цепочка `M502 ; M500`.

**Аргументы:** нет.

**Пример:**
```
M502           ; загрузить заводские настройки (в ОЗУ)
M500           ; записать их в EEPROM для постоянного использования
```

## 32. G34 — Z-тильт (автоматическое выравнивание нескольких Z-двигателей)

**Описание:** принтеры с несколькими независимыми Z-осями (обычно два или три шаговых двигателя) могут использовать G34 для автоматического выравнивания траверсы относительно стола. Измеряет точки над винтами и подстраивает Z-двигатели.

**Аргументы (Marlin – подробно):**

| Аргумент | Значение |
|----------|----------|
| `P<число>` | число итераций (по умолчанию из конфигурации). |
| `A<угол>` | увеличенный допуск на угол наклона. |
| `E<мм>` | максимальная ошибка положения, выше которой – выравнивание. |
| `S<флаг>` | подавление отчётов (S0 — отключить). |
| `Z<мм>` | допустимое отклонение Z для срабатывания коррекции. |
| `V` | подробный вывод. |

**Пример:**
```

G34 V          ; выравнивание с подробным логом
```

**Различия прошивок:**
- **Marlin:** G34 реализована при поддержке нескольких Z-драйверов (`Z_STEPPER_AUTO_ALIGN`). Аргументы могут отличаться в зависимости от версии.
- **Klipper:** аналог – макрос `Z_TILT_ADJUST`. Команда G34 может быть перенаправлена на вызов этого макроса.

## 36. G2 / G3 — дуга по часовой (G2) / против часовой (G3) стрелки

**Описание:** перемещение по дуге окружности в плоскости XY (или другой выбранной плоскости). Используется для криволинейных траекторий в слайсерах с поддержкой Arc Welder.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y` | конечная точка дуги (абсолютно/относительно). |
| `Z`, `E` | координата Z и экструзия в конечной точке (опционально). |
| `I`, `J` | относительные расстояния от начальной точки до центра дуги (R-радиус не всегда поддерживается). |
| `R` | радиус дуги (альтернативный способ задания). |
| `F` | скорость движения. |

**Пример:**
```
G17            ; выбрать плоскость XY
G2 X10 Y5 I5 J0 F1500   ; дуга по часовой до (10,5), центр на 5 мм впереди по X
G3 X0 Y0 R10             ; дуга против часовой стрелки радиусом 10 мм до (0,0)
```

**Различия прошивок:**
- **Marlin:** полная поддержка G2/G3 в плоскости XY, XZ, YZ (определяется G17/G18/G19). Принимает I,J или R.
- **Klipper:** дуги обрабатываются кинематикой. Параметры совпадают с Marlin.

## 58. M907 / M908 — установка / чтение тока двигателей (в процентах или мА)

**Описание:** в Marlin позволяет динамически менять ток на драйверах с поддержкой цифрового управления током (TMC). M907 задаёт ток, M908 — управляет током в режиме ожидания (hold current). Параметры могут быть в процентах (устаревшее) или в миллиамперах.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y`, `Z`, `E` | ток в мА (или в % для старых версий). |

**Пример:**
```
M907 X800 Y800 Z800 E900   ; установить рабочие токи
M908 S50                   ; ток удержания 50% от рабочего
```

**Различия прошивок:**
- **Marlin:** M907/M908 применяются с TMC-драйверами.
- **Klipper:** ток двигателя устанавливается в секции `[tmc2209]` параметром `run_current`; динамическое изменение возможно через `SET_TMC_CURRENT`, но не через M907. Создание макроса решает вопрос.

## 61. M207 / M208 — настройка ретрактов, встроенных в прошивку (Firmware Retract)

**Описание:**
- **M207** — задаёт длину и скорость извлечения (ретракта) пластика, а также Z‑подъём (lift).
- **M208** — задаёт параметры обратной подачи (unretract): длина и скорость.

**Аргументы M207:**

| Аргумент | Значение |
|----------|----------|
| `S<мм>` | длина ретракта (положительное число). |
| `F<мм/мин>` | скорость извлечения. |
| `Z<мм>` | величина Z‑подъёма (Z hop). |

**Аргументы M208:**

| Аргумент | Значение |
|----------|----------|
| `S<мм>` | длина восстановления (обычно равна длине ретракта, но может быть больше). |
| `F<мм/мин>` | скорость восстановительной подачи. |

**Пример:**
```
M207 S5.0 F3000 Z0.4   ; ретракт 5 мм на скорости 3000 мм/мин, Z hop 0.4 мм
M208 S5.0 F1800        ; возврат 5 мм на скорости 1800 мм/мин
```

**Различия прошивок:**
- **Marlin:** полная поддержка.
- **Klipper:** может эмулироваться макросами (`[gcode_macro M207]`), но нативно не реализовано; обычно ретракты задаются слайсером.

## 66. G33 — калибровка Delta-принтера

**Описание:** автоматическая калибровка геометрии дельта-кинематики (endstop positions, tower angles, delta radius). Чрезвычайно важна для качества печати на «дельте».

## 67. M163 / M164 / M165 — смешивание цветов (Mixing Extruder)

**Описание:** управление весами (долями) виртуальных экструдеров в многоканальной головке смешения (например, Diamond Hotend).

- **M163 S<...> P<...>** — задать вес для отдельного виртуального экструдера.
- **M164 S<...>** — сохранить текущие веса как рецепт в слот.
- **M165** — применить смесь (рецепт) по индексу.

**Пример:**
```
M163 S0 P0.8   ; 80% материала из экструдера 0
M163 S1 P0.2   ; 20% из экструдера 1
M164 S0        ; сохранить как рецепт 0
M165 S0        ; активировать рецепт 0 (смешение 80/20)
```

**Различия прошивок:**
- **Marlin:** поддерживается при включённом `MIXING_EXTRUDER`.
- **Klipper:** смешивание настраивается через макросы и параметр `SET_PRESSURE_ADVANCE`; M163..M165 можно реализовать макросами.

M75             ; начать отсчёт времени печати
M76             ; поставить на паузу (например, при смене пластика)
M77             ; остановить и сбросить таймер
```

**Различия прошивок:** идентично (Marlin и Klipper с поддержкой отображения времени).

---

## 79. M81 — выключение питания (ATX Power Off)

**Описание:** выключает питание принтера, если установлено реле управления блоком питания ATX (PS_ON).

**Аргументы:** нет (в некоторых версиях Marlin может быть `S<0/1>`).

**Пример:**
```
M81             ; выключить питание
```

**Различия прошивок:** идентично. В Klipper для управления питанием используется команда `POWER_OFF` или `SET_PIN PIN=psu_pin VALUE=0`.

---

## 80. M85 — отключение при неактивности

**Описание:** автоматически отключает шаговые двигатели и нагреватели после заданного времени бездействия. Аналогична `M84 S...`, но глобальнее.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `S<секунды>` | время неактивности в секундах перед отключением. `S0` — отключить таймер. |

**Пример:**
```
M85 S600        ; отключать всё после 10 минут без движений
M85 S0          ; отключить таймер простоя
```

**Различия прошивок:** идентично.

---

## 81. M200 — диаметр филамента (объёмная экструзия)

**Описание:** задаёт диаметр нити в мм для режима объёмной экструзии. Если включён режим (`M200 D`), слайсер выдаёт G1 E в мм³, а прошивка пересчитывает в длину нити.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `D<мм>` | диаметр филамента (обычно 1.75 или 2.85 мм). |
| `S<0/1>` | (Marlin) 1 — включить объёмный режим, 0 — выключить. |

**Пример:**
```
M200 D1.75      ; установить диаметр 1.75 мм
M200 S1         ; активировать объёмную экструзию
```

**Различия прошивок:**
- **Marlin:** полная поддержка при `VOLUMETRIC_EXTRUSION`.
- **Klipper:** объёмная экструзия не поддерживается нативно; редко используется. Команда может игнорироваться.

---

## 82. M301 — PID-коэффициенты сопла (Marlin)

**Описание:** устанавливает вручную коэффициенты ПИД-регулятора экструдера (обычно после автотюна M303). В Klipper аналогично `SET_HEATER_PID HEATER=extruder ...`.

**Аргументы (Marlin):**

| Аргумент | Значение |
|----------|----------|
| `P`, `I`, `D` | пропорциональный, интегральный, дифференциальный коэффициенты. |
| `C<значение>` | (опционально) номер цикла для многоканального PID. |
| `E<индекс>` | номер экструдера (по умолчанию 0). |

**Пример:**
```
M301 P22.20 I1.08 D114.00   ; задать PID для E0
```

**Различия прошивок:**
- **Marlin:** M301 используется.
- **Klipper:** PID назначается через `SET_HEATER_PID HEATER=extruder PID_KP=...`.

---

## 83. M118 — вывод сообщения в хост-терминал

**Описание:** отправляет текстовую строку напрямую в последовательный порт (на компьютер), минуя LCD. Используется для логирования или команд хосту.

**Аргументы:** текстовая строка (без кавычек).

**Пример:**
```
M118 Слой 1 завершён, старт слоя 2
```

**Различия прошивок:** идентично.

---

## 84. M120 / M121 — push / pop состояние концевиков

**Описание:**
- **M120** — сохраняет текущее состояние концевых выключателей.
- **M121** — восстанавливает ранее сохранённое состояние.

Позволяет временно отключить/включить концевые выключатели без перенастройки.

**Аргументы:** нет.

**Пример:**
```
M120            ; запомнить, какие датчики активны
M121            ; восстановить их состояние
```

**Различия прошивок:** поддерживаются только в Marlin (опция `ENDSTOP_INTERRUPTS_FEATURE`). В Klipper не используются.

---

## 85. M240 — снимок с камеры

**Описание:** посылает сигнал на подключённую камеру (обычно через триггерный пин) для создания фотоснимка.

**Аргументы:** нет (или `S<0/1>` для некоторых реализаций).

**Пример:**
```
M240            ; сделать снимок
```

**Различия прошивок:** идентично (через `TRIGGER_PIN`). В Klipper может быть реализовано через макрос `PHOTO` с `SET_PIN`.

---

## 86. M360 — информация о SD-карте

**Описание:** выводит отчёт о SD-карте: файлы, занимаемое место, объём. Полезно для просмотра содержимого через терминал.

**Аргументы:** нет (или `S<номер файла>` для деталей).

**Пример:**
```
M360            ; показать список файлов на SD
```

**Различия прошивок:**
- **Marlin:** реализована при `SDSUPPORT`.
- **Klipper:** аналог — `SDCARD_PRINT_FILE` и команды виртуальной SD-карты, но M360 может работать как макрос.

---

## 87. M603 — конфигурация датчика филамента (Marlin)

**Описание:** задаёт поведение датчика филамента (Filament Runout Sensor): какие действия выполнять при обрыве, минимальную длину и т.д. Дополняет M412.

**Аргументы (Marlin):**

| Аргумент | Значение |
|----------|----------|
| `S<0/1>` | 1 — включить, 0 — выключить. |
| `R<мм>` | минимальная длина филамента до срабатывания. |
| `P<...>` | тип действия: 0 — пауза, 1 — смена филамента (M600). |
| `T<индекс>` | номер экструдера. |

**Пример:**
```
M603 S1 R20 P1 T0    ; включить датчик, 20 мм буфер, по обрыву запускать M600
```

**Различия прошивок:**
- **Marlin:** поддерживается.
- **Klipper:** настройки делаются в секции `[filament_switch_sensor]`. M603 не нативная, может быть эмулирована.

---

## 88. M906 — ток шаговых двигателей (в мА, TMC)

**Описание:** устанавливает рабочий ток в миллиамперах для моторов с TMC-драйверами (аналог M907, но в мА). Используется для точной настройки без риска перегрева.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y`, `Z`, `E` | ток в мА для соответствующей оси. |
| `T<индекс>` | для экструдера — номер (E0, E1…). |

**Пример:**
```
M906 X800 Y800 Z800 E900   ; задать ток 800 мА на X,Y,Z и 900 мА на экструдер
```

**Различия прошивок:**
- **Marlin:** поддерживается (требует TMC).
- **Klipper:** нативный способ — `SET_TMC_CURRENT STEPPER=... CURRENT=...`. M906 обычно реализуется макросом.

---

## 89. G38.2 / G38.3 — прямой пробинг (Straight Probe)

**Описание:** перемещает ось в заданном направлении до срабатывания датчика (зонда). G38.2 останавливается при касании, G38.3 продолжает движение после касания до потери контакта. Используется для точного позиционирования или калибровки.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y`, `Z` | направление и расстояние движения. |
| `F<мм/мин>` | скорость пробинга. |
| `P<мм>` | максимальное расстояние для G38.3 после потери контакта (только Marlin). |

**Пример:**
```
G38.2 Z-10 F100    ; опускать Z на 10 мм со скоростью 100 мм/мин, пока не сработает датчик
G38.3 X20 F200     ; двигать X вперёд, фиксируя и потерю контакта
```

**Различия прошивок:**
- **Marlin:** поддерживается при `PROBE_PIN` и `Z_PROBE_ALLOWED`.
- **Klipper:** аналогичная команда `PROBE` или `PROBE_ACCURACY`; G38.2/3 могут работать, если включены в конфигурации.

---

## 90. M43 — отладка пинов и тест драйверов

**Описание:** диагностическая команда Marlin, позволяющая проверить состояние пинов, включить/выключить их, а также протестировать драйверы шаговых двигателей.

**Аргументы (Marlin):**

| Аргумент | Значение |
|----------|----------|
| `S<0/1>` | 0 — отчёт о пинах, 1 — тест сигналов. |
| `P<пин>` | номер пина. |
| `E<индекс>` | (для теста драйверов) выбор экструдера. |
| `W` | (Marlin) сохранить отчёт в файл. |

**Пример:**
```
M43 S0          ; вывести список пинов и их состояний
M43 S1 P44      ; включить/выключить пин 44 для проверки
```

**Различия прошивок:**
- **Marlin:** только для отладки.
- **Klipper:** не поддерживается; отладка через команды `QUERY_ENDSTOPS`, `QUERY_PIN`.

---

## 91. M911 — сохранение состояния при отказе питания (Power Loss Recovery)

**Описание:** активирует режим восстановления после сбоя питания (если есть аппаратная поддержка). Принтер периодически сохраняет позицию в EEPROM.

**Аргументы:** нет (или `S<0/1>` для включения/выключения).

**Пример:**
```
M911 S1         ; включить восстановление после сбоя питания
M911 S0         ; отключить
```

**Различия прошивок:**
- **Marlin:** требует `POWER_LOSS_RECOVERY`.
- **Klipper:** не поддерживает автоматическое восстановление после отключения питания; для возобновления печати обычно используют макросы с сохранением состояния в `save_variable`.

---

## 92. M913 — Hybrid Threshold (TMC StealthChop / SpreadCycle)

**Описание:** устанавливает пороговую скорость, ниже которой драйвер работает в тихом режиме StealthChop, а выше — в мощном SpreadCycle. Помогает избежать пропусков шагов на высокой скорости.

**Аргументы (Marlin):**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y`, `Z`, `E` | пороговая скорость в мм/мин для перехода. |
| `T<индекс>` | номер экструдера. |

**Пример:**
```
M913 X30 Y30 Z5 E30   ; переходить в SpreadCycle при >30 мм/с (1800 мм/мин)
```

**Различия прошивок:**
- **Marlin:** поддерживается с TMC-драйверами.
- **Klipper:** настройка через `[tmc2209]` параметр `stealthchop_threshold`. M913 эмулируется макросом.

---

## 93. M914 — StallGuard threshold (бессенсорный хоминг)

**Описание:** задаёт чувствительность StallGuard для TMC-драйверов при бессенсорном поиске дома (sensorless homing). Чем меньше число, тем выше чувствительность к удару.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y`, `Z` | значение StallGuard (-64..63) для оси. |
| `S<значение>` | (Klipper) чувствительность (`SET_TMC_FIELD`). |

**Пример:**
```
M914 X10 Y10    ; установить чувствительность 10 для X и Y
```

**Различия прошивок:**
- **Marlin:** M914 меняет чувствительность на лету.
- **Klipper:** бессенсорный хоминг настраивается в `[tmc2209]` параметром `diag_pin` и `driver_SGT`; M914 не встроена, реализуется через `SET_TMC_FIELD`.

---

## 94. M915 — минимальная скорость для бессенсорного хоминга

**Описание:** задаёт минимальную скорость, с которой движение будет расцениваться как хоминг при использовании StallGuard (чтобы исключить ложные срабатывания при медленных движениях).

**Аргументы (Marlin):**

| Аргумент | Значение |
|----------|----------|
| `X`, `Y`, `Z` | минимальная скорость в мм/мин. |

**Пример:**
```
M915 X500 Y500   ; только при скорости >500 мм/мин срабатывает датчик удара
```

**Различия прошивок:**
- **Marlin:** поддерживается.
- **Klipper:** параметр задаётся в конфиге `homing_retract_dist` и `driver_SGTHRS`, M915 отсутствует.

---

## 95. M918 — подсветка LCD (дисплея)

**Описание:** управляет яркостью подсветки LCD-экрана. Позволяет приглушить экран на ночь или для экономии энергии.

**Аргументы:**

| Аргумент | Значение |
|----------|----------|
| `P<яркость>` | 0–255 (0 — выключено, 255 — максимум). |

**Пример:**
```
M918 P128       ; установить подсветку на 50%
M918 P0         ; выключить экран
```

**Различия прошивок:**
- **Marlin:** работает при `LCD_BRIGHTNESS_CONTROL`.
- **Klipper:** LCD управляется через `SET_LCD_BRIGHTNESS`; M918 может быть создана макросом.

---

## 96. M997 — обновление прошивки (для плат с bootloader)

**Описание:** запускает процесс обновления прошивки из SD-карты или другой памяти (если bootloader это поддерживает). Используется для прошивки "по воздуху".

**Аргументы:** нет (или имя файла).

**Пример:**
```
M997            ; перезагрузиться в режим обновления
```

**Различия прошивок:** идентично (зависит от платформы). В Klipper обновление выполняется через SSH и перезапись хоста, не через M997.

# Синтаксис и архитектура G‑кода для 3D‑печати

В этой статье разбирается, как устроена программа на G-коде, из чего складывается строка, как прошивка интерпретирует команды и как строится взаимодействие между слайсером, хостом и принтером. Знание этих основ необходимо для осмысленного написания стартовых скриптов, макросов и диагностики.

---

## 1. Анатомия строки G-кода

Типичная строка выглядит так:

```
G1 X100 Y50 Z0.3 E0.5 F1500 ; перемещение с экструзией
```

### 1.1. Номер строки (опционально)
`N<число>` — идентификатор строки, используется для проверки целостности передачи данных и восстановления печати после сбоя. В повседневном коде от слайсера номера строк обычно **отсутствуют**, их добавляют специальные хост-программы (OctoPrint при отправке с контрольной суммой).

```
N123 G1 X10 Y10 *119
```
Символ `*` и контрольная сумма автоматически вычисляются при включённой проверке чек-суммы. В файлах слайсера вы этого не встретите.

### 1.2. Команда (буква + число)
`G` или `M`, за которым следует целое число (иногда с суффиксом, например `G38.2`). Определяет действие: движение, нагрев, настройку и т.д. Регистр важен: `g1` и `G1` – допустимы, но заглавные буквы — стандарт.

### 1.3. Параметры (аргументы)
Состоят из буквы латинского алфавита и числа. Буква определяет, к какой оси или свойству относится значение.

| Буква | Типичное значение |
|-------|-------------------|
| `X`, `Y`, `Z` | координаты назначения (мм) |
| `E` | длина подачи филамента (мм) |
| `F` | скорость подачи (мм/мин) |
| `S` | температура (°C), скорость вентилятора (0-255 или 0.0-1.0), номер слота и т.д. |
| `P` | время паузы (мс), номер инструмента, индекс вентилятора и пр. |
| `R` | радиус дуги, температура ожидания (для M109/M190) |
| `I`, `J`, `K` | смещения центра дуги по осям X, Y, Z |
| `T` | номер инструмента (экструдера) |
| `A`, `B`, `C` | реже — углы Эйлера, параметры датчиков |

**Правила:**
- Пробелы между параметрами **не обязательны**, но рекомендуются для читаемости.
- Порядок параметров значения не имеет: `G1 X10 Y20` = `G1 Y20 X10`.
- Значения могут быть дробными (точка как разделитель): `X100.5`, `E0.05`.
- Не указанные в команде оси **сохраняют предыдущее состояние** (модальность).

### 1.4. Комментарии
Символ `;` (точка с запятой) — всё, что после него до конца строки, игнорируется прошивкой. Используется для пояснений и временного отключения команд.

```
M104 S210 ; нагрев сопла до 210
;G1 X50 Y50 F3000 — эта строка не выполнится
```

**Klipper дополнительно** поддерживает комментарии в стиле Python (`#`), но в стандартном G-коде для совместимости принят только `;`.

---

## 2. Модальные и немодальные команды

**Модальные** — команды, которые изменяют состояние машины, сохраняющееся до следующей смены.  
**Немодальные** — действуют однократно и не меняют долговременных настроек.

| Тип команды | Пример | Модальность |
|-------------|--------|-------------|
| Движение (G0/G1) | `G1 X10` | Модальная: последующие G1 без указания `F` сохранят последнюю скорость. |
| Единицы измерения (G20/G21) | `G21` | Модальная: все координаты далее интерпретируются как миллиметры, пока не встретится G20. |
| Позиционирование (G90/G91) | `G90` | Модальная: абсолютные координаты, пока не переключится G91. |
| Экструзия (M82/M83) | `M83` | Модальная: режим интерпретации `E`. |
| Нагрев с ожиданием (M109) | `M109 S210` | Немодальная (выполняется однократно, после завершения режим не меняется). |
| Установка позиции (G92) | `G92 E0` | Немодальная: изменяет текущие координаты, но не создаёт режима. |
| Пауза (G4) | `G4 P1000` | Немодальная. |

Модальность — ключевая концепция, позволяющая слайсеру не повторять `F` и `G90` перед каждым движением. Файл печати обычно содержит однократные установки в начале, а затем только координаты.

---

## 3. Системы координат и смещения

Принтер оперирует несколькими уровнями координат:

### 3.1. Машинные координаты (Machine Coordinates)
Абсолютная система, привязанная к концевым выключателям. После выполнения `G28` (хоминг) оси устанавливаются в известное положение (обычно `X=0 Y=0 Z=0` в точке срабатывания датчиков). Они отражают реальное положение механики.

### 3.2. Рабочие координаты (Work Coordinates)
Смещённая относительно машинных нуля точка, выбираемая командами `G54`…`G59` или `G92`. По умолчанию активна `G54`. Слайсер генерирует координаты именно в рабочей системе.

Связь: **Рабочая координата = Машинная координата — Смещение (G54/55…)**.  
После `G28` смещения могут сбрасываться или восстанавливаться (зависит от прошивки и параметра `G28 O/R`).

### 3.3. Относительные координаты (при G91)
Когда активен относительный режим (G91), координаты трактуются как приращение от текущей позиции, а не от начала координат.

### 3.4. G92 и виртуальное смещение
`G92 X0 Y0 Z0` временно сдвигает рабочую систему координат без изменения машинной. Применяется для локального обнуления (например, перед стартом печати `G92 E0` обнуляет счётчик экструзии). Это смещение **сбрасывается** при `G92.1`, а также может быть сброшено хомингом (зависит от прошивки).

### 3.5. Probe Z-offset (M851 / SET_GCODE_OFFSET)
Специфическое смещение по Z, компенсирующее разницу между срабатыванием датчика автоуровня и реальным касанием сопла. В Klipper оно задаётся через `SET_GCODE_OFFSET Z_ADJUST=...`, в Marlin — `M851 Z-...`. Это смещение **применяется поверх** рабочих координат, активно влияя на первый слой.

---

## 4. Порядок выполнения и буферизация движений

### 4.1. Планировщик движений (Motion Planner)
Прошивка не выполняет команды строго построчно. Она читает строки в **буфер опережающего чтения** и заносит планируемые перемещения в очередь движений (look-ahead). Это необходимо для плавного прохождения углов без остановок.

- **Marlin:** размер буфера обычно 16 команд. Планировщик анализирует несколько будущих движений, чтобы рассчитать допустимую скорость входа в угол (jerk/ junction deviation).
- **Klipper:** выносит планирование на хост-компьютер (Raspberry Pi), что даёт практически безграничный буфер и сложные алгоритмы сглаживания (Input Shaper). Klipper получает команды, переводит их в траекторию с микросегментами и отдаёт шаговые импульсы микроконтроллеру.

**Следствие:** нельзя мгновенно изменить параметры движения «на лету» внутри очереди. Например, если вы отправили `G1 X100 F3000`, а сразу после — `M220 S50` (замедление), то первое движение уже могло быть запланировано с исходной скоростью. Для синхронизации применяется `M400` (ожидание опустошения очереди).

### 4.2. Команды реального времени (Real-Time Commands)
Некоторые команды обрабатываются немедленно, без ожидания очереди:
- `M112` (аварийная остановка) — прерывает всё.
- `M410` (быстрая остановка в Marlin).
- В Klipper — команды типа `RESTART`, `FIRMWARE_RESTART`, а также все команды, начинающиеся с `!` (экстренные).
- `M108` (отмена ожидания нагрева) — позволяет прервать M109/M190.

### 4.3. Влияние M400
`M400` ожидает, пока все запланированные движения завершатся. После этого можно безопасно менять настройки, которые влияют на следующие ходы (например, `M92`, `M350`).

---

## 5. Генерация G-кода: от слайсера к файлу печати

Слайсер (Cura, PrusaSlicer, SuperSlicer и др.) преобразует 3D-модель (STL/STEP) в последовательность G-кода. Процесс:

1. **Разбиение на слои** — модель нарезается горизонтальными плоскостями с заданной высотой слоя.
2. **Генерация траекторий** — для каждого слоя строится периметр, заполнение, поддержки и т.д.
3. **Расчёт экструзии** — на основе ширины линии и высоты слоя вычисляется длина подачи `E`.
4. **Сборка в файл** — добавляются стартовый и конечный G-код из настроек принтера.

**Типичная структура файла:**

```
; Стартовый G-код (из настроек слайсера)
G90               ; абсолютные координаты
M82               ; абсолютная экструзия
M140 S60          ; нагрев стола
M190 S60          ; ожидание
M104 S210         ; нагрев сопла (без ожидания)
G28               ; хоминг
M420 S1           ; включить сохранённую сетку
G1 Z5 F3000       ; подъём
G1 X... Y...      ; подъезд к старту
M109 S210         ; ждать нагрева сопла
; Начало печати
G92 E0            ; сброс экструзии
G1 ...            ; линии продувки, юбка, первый слой
; Слои
;LAYER:0
G1 X... Y... E... ; движения слоя
...
;LAYER:1
...
; Завершающий G-код
M107              ; выключить вентилятор
G91               ; относительные координаты
G1 Z+10 F600      ; отвести стол
G90               ; абсолютные координаты
G1 X0 Y200 F6000  ; представить модель
M104 S0           ; выключить сопло
M140 S0           ; выключить стол
M84               ; отключить двигатели
```

Особенности:
- Координаты в файле — **рабочие** (обычно от переднего левого угла стола).
- Скорость `F` не дублируется на каждой строке, если она не меняется.
- Значение `E` может сбрасываться командой `G92 E0` на каждом слое или в начале печати (зависит от настроек).

---

## 6. Взаимодействие компонентов: хост, прошивка, принтер

### 6.1. Хост-программа
OctoPrint, Pronterface, Mainsail/Fluidd (для Klipper) отправляют команды по последовательному соединению (USB) или через виртуальный COM-порт. Хост может:
- Передавать файл построчно.
- Посылать команды вручную (терминал).
- Управлять принтером: пауза, отмена, подстройка температуры.

**Важно:** Хост не интерпретирует G-код, он только транспортирует его прошивке. Исключение — Klipper, где хост-процесс (`klippy`) сам является интерпретатором, а микроконтроллер — лишь исполнителем шагов.

### 6.2. Прошивка (Marlin / Klipper)
- **Marlin:** единый бинарный файл на микроконтроллере, содержащий и логику G-кода, и управление шаговыми драйверами. Все настройки компилируются заранее.
- **Klipper:** разделяет роли: высокоуровневую обработку G-кода и кинематику ведёт Python-приложение на одноплатном компьютере, а на плате принтера — маленькая программа, выполняющая только шаговые импульсы и чтение датчиков.

**Различие в интерпретации команд:**
- **Marlin:** каждая команда реализована в коде прошивки. Набор доступных команд жёстко определён опциями компиляции.
- **Klipper:** можно динамически создавать макросы с произвольной логикой. Команды могут быть переопределены пользователем без перепрошивки. Например, можно создать макрос `[gcode_macro M600]`, и он будет вызываться вместо отсутствующего встроенного M600.

### 6.3. Обратная связь
Хост получает от прошивки ответы:
- `ok` — команда выполнена (или помещена в буфер).
- `T:210 / B:60` — сообщения о температуре.
- `echo:...` — отладочная информация.

Klipper использует протокол на основе JSON с более богатыми ответами, но для совместимости эмулирует и текстовые ответы.

---

## 7. Особенности синтаксиса в Klipper

Klipper привносит ряд расширений и отличий, которые нужно знать:

### 7.1. Дробные значения для вентиляторов и яркости
`M106 S0.5` – установить скорость 50% (вместо 0-255). Диапазон 0.0-1.0 предпочтителен, но если вентилятор сконфигурирован с `max_power: 1.0`, то поддерживается и 0-255 для обратной совместимости.

### 7.2. Относительные перемещения экструдера без переключения режима
Klipper позволяет выполнять относительную экструзию внутри абсолютного режима с помощью команды `M83`, но также поддерживает запись `G1 E+5` (с явным знаком) в любом режиме, что не всегда корректно в Marlin. **Рекомендуется всегда использовать стандартный способ**: `M83` и `G1 E5`.

### 7.3. Комментарии и макросы
В Klipper макросы пишутся на языке шаблонов Jinja2, что даёт возможность использовать переменные, условия, циклы внутри G-кода. Например:

```
[gcode_macro PURGE_LINE]
gcode:
    SAVE_GCODE_STATE NAME=purge_state
    G90
    G1 X10 Y10 F3000
    G1 E10 F200
    RESTORE_GCODE_STATE NAME=purge_state
```

В обычном слайсерном G-коде вы не увидите Jinja2, но при написании собственных макросов это мощный инструмент.

### 7.4. Команды с префиксом `SET_`, `QUERY_`, `SAVE_`
Klipper активно использует расширенные команды, не являющиеся стандартным G-кодом:
- `SET_GCODE_OFFSET Z_ADJUST=0.05`
- `SET_HEATER_TEMPERATURE HEATER=extruder TARGET=210`
- `QUERY_ENDSTOPS`

Они не являются частью традиционного G-кода, но часто встраиваются в макросы с привычными именами (M109, M190 и т.д.).

### 7.5. Парковка и хоминг
В Klipper G28 без параметров выполняет хоминг всех осей в порядке, определённом конфигом. Для раздельного хоминга указываются оси: `G28 X Y`. Параметры Marlin вроде `O`, `L` не поддерживаются.

---

## 8. Типовые ошибки синтаксиса и правила отладки

- **Забытая точка с запятой** — строка без комментария выполняется. Если вы хотели закомментировать команду, но не поставили `;`, она будет исполнена.
- **Регистр адресов** — `G1 x100` (строчная `x`) может быть проигнорирована некоторыми прошивками. Всегда пишите адреса заглавными: `X100`.
- **Пробелы после `;`** — допустимы, комментарий начинается сразу после `;`.
- **Слишком высокая скорость подачи (`F`)** — если задать `F` больше максимальной скорости оси, прошивка ограничит её. В Klipper ограничение настраивается в `[printer] max_velocity`.
- **Конфликт модальных состояний** — если файл начат с `G91` (относительные координаты), а слайсер ожидает абсолютные, то принтер уедет в непредсказуемую точку. Поэтому стартовый G-код всегда начинают с `G90`.
- **Проверка в терминале** — перед запуском сложного макроса полезно выполнить его построчно вручную, наблюдая за ответами.

# Синтаксис и архитектура G-кода для 3D-печати

Здесь подробно разбирается, как устроена программа на G-коде: из чего состоит строка, какие бывают команды и аргументы, как они обрабатываются прошивкой, чем отличается поведение в Marlin и Klipper. Знание этих принципов позволяет писать стартовые скрипты, макросы и грамотно диагностировать проблемы.

---

## 1. Строка G-кода — базовая структура

Каждая строка — это одна команда с аргументами. Общий вид:

```
[номер_строки] команда [аргументы] [;комментарий]
```

Квадратные скобки означают необязательные элементы.

### 1.1. Номер строки (N…)
Необязательный префикс `N` с целым числом, за которым может следовать контрольная сумма `*<число>`. Используется для проверки целостности передачи данных и для возобновления печати после сбоя. В слайсерных файлах номера строк обычно отсутствуют.

**Пример с контрольной суммой:**
```
N123 G1 X10 Y20 *119
```
Прошивка вычисляет XOR всех байт между `N` и `*` и сравнивает с `119`. При несовпадении — ошибка, команда отклоняется. В повседневной работе этот механизм включается хостом (например, OctoPrint) и не обязателен.

### 1.2. Команда
Буква латинского алфавита и целое число. Основные префиксы:

| Буква | Назначение |
|-------|------------|
| `G` | общецелевые движения, единицы измерения, координатные системы |
| `M` | настройки, нагрев, управление периферией, диагностика |
| `T` | выбор инструмента (экструдера) |

Число может быть дробным у специальных команд (например, `G38.2` — пробинг). Регистр буквы обычно не важен (`g1` = `G1`), но заглавные — стандарт. Пробел между буквой и числом **не допускается** (`G 1` — ошибка).

### 1.3. Аргументы (параметры)
Записываются в формате `БукваЗначение`. Буква определяет ось или свойство, значение — число. Примеры:

`X100`, `Y-50.3`, `Z0.2`, `E5`, `F1500`, `S210`, `P1000`

- Порядок аргументов **произволен**.
- Пробелы между аргументами не обязательны, но допустимы и улучшают читаемость.
- Повтор аргумента в одной строке: поведение не определено (может использоваться последнее значение или вызвать ошибку). Следует избегать.
- Пропущенные аргументы **сохраняют предыдущее значение** соответствующего параметра (модальность).
- Значения могут быть отрицательными, дробными (разделитель — точка), в экспоненциальной записи (редко, поддерживается не всегда).

### 1.4. Комментарии
Начинаются с символа `;` (точка с запятой). Всё до конца строки игнорируется. Часто используются для пояснений и временного отключения команд.

```
G1 X100 Y50 ; перемещение в точку
;G1 X200 — закомментировано, не выполнится
```

**Klipper** дополнительно допускает комментарии в стиле Python (`#`), но в слайсерных файлах лучше использовать `;` для совместимости.

---

## 2. Типы команд и принцип модальности

Команды делятся на **модальные** и **немодальные**.

### 2.1. Модальные команды
Устанавливают режим, который сохраняется до явной отмены другой командой. Ключевые модальные состояния:

| Группа | Команды | Что запоминается |
|--------|---------|------------------|
| Перемещение | `G0`, `G1`, `G2`, `G3` | Скорость подачи `F` (действует для последующих G0/G1 без `F`) |
| Единицы | `G20` (дюймы), `G21` (мм) | Все координаты интерпретируются в заданных единицах |
| Позиционирование | `G90` (абсолютное), `G91` (относительное) | Как понимать координаты X,Y,Z |
| Экструзия | `M82` (абсолютная), `M83` (относительная) | Как интерпретируется ось E |
| Рабочая плоскость | `G17` (XY), `G18` (XZ), `G19` (YZ) | В какой плоскости выполняются дуги (G2/G3) и коррекция |
| Система координат | `G54` … `G59` | Выбор активной рабочей системы координат (смещение от машинного нуля) |

Модальность позволяет не дублировать настройки в каждой строке. Например:
```
G21 G90 M82     ; установили мм, абсолютные координаты XYZ и E
G1 F3000        ; задали скорость
G1 X10 Y10 E5   ; перемещение с этой скоростью
G1 X20 Y20 E10  ; скорость F3000 всё ещё активна
```

### 2.2. Немодальные команды
Выполняются однократно и не меняют долговременных режимов. Примеры: `G4` (пауза), `G28` (хоминг), `M109` (нагрев с ожиданием), `G92` (установка текущей позиции). Однако `G92` меняет рабочее смещение, которое может сбрасываться при последующем хоминге — это особенность, а не модальность.

### 2.3. Команды реального времени
Некоторые команды обрабатываются немедленно, прерывая очередь движений:
- `M112` — аварийная остановка.
- `M410` — быстрая остановка (Marlin).
- `M108` — отмена ожидания нагрева (прерывает M109/M190).
- В Klipper: команды, начинающиеся с `!`, а также `RESTART`, `FIRMWARE_RESTART`.

Они не ждут завершения буфера и применяются мгновенно.

---

## 3. Аргументы — полный перечень для 3D-печати

Ниже перечислены все значимые адреса, их типы и смысл.

| Адрес | Назначение | Пример значения |
|-------|------------|-----------------|
| `X` | координата X, мм | `X100.5` |
| `Y` | координата Y, мм | `Y-20` |
| `Z` | координата Z, мм | `Z0.3` |
| `E` | длина подачи/отката филамента, мм | `E5.2` |
| `F` | скорость подачи, мм/мин | `F1500` |
| `S` | температура (°C), скорость вентилятора (0-255 или 0.0-1.0 в Klipper), номер слота, яркость, чувствительность | `S210`, `S128`, `S0.5` |
| `P` | время (мс), номер инструмента, индекс вентилятора, номер слота памяти | `P1000`, `P0` |
| `R` | радиус дуги, температура ожидания (M109 R…), расстояние (G38.3) | `R10`, `R150` |
| `I` | смещение центра дуги по X от начальной точки | `I5` |
| `J` | смещение центра дуги по Y от начальной точки | `J0` |
| `K` | смещение центра дуги по Z (при G18/G19) | `K3` |
| `T` | номер инструмента (экструдера) | `T0`, `T1` |
| `N` | номер строки с контрольной суммой | `N123` |
| `*` | контрольная сумма (XOR от N до *) | `*119` |
| `Q` | в Marlin: дополнительный параметр для некоторых команд (например, подавление отчёта в G29) | `Q1` |
| `V` | в Marlin: подробный вывод (verbose) | `V` (без значения) |
| `L` | индекс сетки, количество, нагрузка | `L0` |
| `H` | высота, флаг | `H5` |
| `U`, `B`, `C`, `D` | используются в специфических командах (PID, диаметр филамента, тестовый шаблон) | – |

**Правила работы с аргументами:**
- Число после буквы обязательно, исключение — некоторые флаги вроде `V` (M503 V), но это редкость.
- Адреса чувствительны к регистру: `X` и `x` могут быть разными (в Marlin обычно оба работают, но лучше придерживаться верхнего регистра).
- Неизвестные адреса игнорируются (прошивка может выдать предупреждение).

---

## 4. Системы координат и смещения

Принтер оперирует несколькими слоями систем координат.

### 4.1. Машинные координаты (machine coordinates)
Абсолютная система, привязанная к концевым выключателям. После команды `G28` (хоминг) оси устанавливаются в известное положение, обычно `X0 Y0 Z0` в точке срабатывания датчиков. Эти координаты отражают реальное положение механики и не подлежат сбросу софтовыми смещениями (кроме M206).

### 4.2. Рабочие координаты (work coordinates)
Выбираются командами `G54`–`G59`. Каждая хранит заранее заданное смещение (home offset), которое прибавляется к машинным координатам. По умолчанию активно `G54` со смещением, установленным через `M206`. Слайсер генерирует координаты именно в этой системе.

Формула: **Рабочая_координата = Машинная_координата + Смещение_G54_…59 + Текущие_сдвиги_G92**

Смещения G54…G59 сохраняются в EEPROM (M500) и не сбрасываются хомингом (если не заданы специальные опции Marlin).

### 4.3. Смещение через G92
`G92 X… Y… Z… E…` временно сдвигает рабочую систему, изменяя текущие координаты без движения. Например, `G92 X0 Y0` делает текущую точку нулём рабочей системы. Это смещение **сбрасывается** при:
- выключении питания,
- `G92.1` (сброс всех осей),
- хоминге (зависит от прошивки и параметров G28).

Применяется для обнуления счётчика экструзии (`G92 E0`) и локальных сдвигов.

### 4.4. Probe Z-offset
Специфичное смещение по Z, компенсирующее разницу между точкой срабатывания датчика автоуровня и реальным соплом. Задаётся:
- Marlin: `M851 Z-1.23`
- Klipper: `SET_GCODE_OFFSET Z_ADJUST=-1.23` (или через макрос `M851`)

Это смещение действует **поверх** рабочих координат, влияя на первый слой.

### 4.5. Бабистеппинг (M290 / Z_ADJUST)
Ручная подкрутка Z в процессе печати. Не меняет сохранённый Z-offset, только текущую позицию. В Marlin: `M290 Z0.02`, в Klipper: `SET_GCODE_OFFSET Z_ADJUST=+0.02`.

---

## 5. Очередь движений и выполнение команд

Прошивка не выполняет G-код построчно. Она использует **буфер опережающего чтения** и планировщик движений для плавного прохождения углов.

### 5.1. Буферизация
- **Marlin:** размер буфера обычно 16 команд. Планировщик анализирует несколько будущих перемещений, рассчитывая допустимую скорость на стыках (jerk/junction deviation).
- **Klipper:** планировщик работает на хост-компьютере (Raspberry Pi), буфер практически безграничен. Прошивка на плате лишь получает шаговые импульсы.

Из-за буферизации изменение параметров «на лету» может задержаться. Например, если после `G1 X100 F3000` сразу отправить `M220 S50` (замедление), первое движение может уже уйти в планировщик с исходной скоростью. Для синхронизации применяют `M400` — ждать опустошения очереди.

### 5.2. Порядок обработки
1. Хост отправляет строку (или она читается с SD-карты).
2. Прошивка парсит строку, проверяет корректность.
3. Для движений — команда помещается в очередь движений.
4. Для немодальных команд (M109, G4) — выполняется сразу, но может ожидать завершения текущих движений, если не является командой реального времени.
5. Планировщик непрерывно берёт из очереди сегменты и генерирует шаги.

### 5.3. Команды, ожидающие завершения движения
Некоторые команды автоматически ждут опустошения буфера, даже без `M400`:
- `G28` (хоминг)
- `G29` (автоуровень)
- `M109`, `M190` (нагрев с ожиданием)
- `M400` (явное ожидание)

### 5.4. Чтение с SD-карты
При печати с SD-карты прошивка сама читает файл. В этом режиме команды типа `M25` (пауза) и `M24` (продолжить) управляют потоком.

---

## 6. Генерация G-кода: от слайсера к файлу

Слайсер (Cura, PrusaSlicer, SuperSlicer) преобразует 3D-модель в последовательность команд.

**Общая структура файла:**

```
; === Стартовый G-код ===
G90               ; абсолютные координаты
M82               ; абсолютная экструзия
M140 S60          ; нагрев стола
M190 S60          ; ждать стол
M104 S210         ; предварительный нагрев сопла
G28               ; хоминг
M420 S1           ; включить сетку выравнивания
G1 Z5 F3000       ; поднять сопло
G1 X... Y...      ; позиция начала печати
M109 S210         ; ждать нагрев сопла
G92 E0            ; обнулить экструзию
; ... линии продувки

; === Слои ===
;LAYER:0
G1 X... Y... E... ; движения первого слоя
...
;LAYER:1
...

; === Завершающий G-код ===
M107              ; выключить вентилятор
G91               ; относительные координаты
G1 Z+10 F600      ; отвести стол
G90               ; абсолютные координаты
G1 X0 Y200 F6000  ; представить модель
M104 S0           ; выключить сопло
M140 S0           ; выключить стол
M84               ; отключить двигатели
```

**Особенности генерации:**
- Скорость `F` не повторяется на каждой строке, если не меняется.
- Координата `E` может сбрасываться `G92 E0` на каждом слое или в начале, в зависимости от настроек слайсера.
- Слайсеры могут использовать относительную экструзию (`M83` + `G1 E5`), что облегчает повторное использование кода без сброса E.

**Пре-/пост-процессоры** (например, в PrusaSlicer) могут модифицировать G-код: добавлять команды в начало/конец слоя, заменять дуги (Arc Welder), вставлять кастомные скрипты.

---

## 7. Различия синтаксиса Marlin и Klipper

| Элемент | Marlin | Klipper |
|---------|--------|---------|
| Скорость вентилятора M106 | `S0`–`255` (целое) | `S0.0`–`1.0` (дробное); также понимает 0–255, если `max_power: 1.0` |
| Комментарии | только `;` | `;` и `#` |
| Переопределение команд | невозможно, только перекомпиляция | можно создавать макросы с произвольной логикой (Jinja2) |
| Аргументы с явным знаком | `G1 X+10` — может игнорироваться | `G1 X+10` — допустимо, эквивалентно `G91` + `G1 X10` |
| Неизвестные команды | игнорируются или вызывают ошибку | вызывают предупреждение, если не определены как макросы |
| Команды настройки PID, смещений, токов | встроенные M301, M304, M906 | заменены на `SET_HEATER_PID`, `SET_TMC_CURRENT`, `SET_GCODE_OFFSET` и т.д. |
| M109 / M190 | нативная поддержка S и R | обычно реализованы как макросы с использованием `TEMPERATURE_WAIT` |
| G29 (автоуровень) | обширный набор параметров, зависит от конфигурации | по умолчанию вызывает `BED_MESH_CALIBRATE`, если настроен |
| Управление экструзией | M82/M83, M221 (поток) | идентично, но M221 также поддерживается |
| Датчик филамента | M412, M603 | настраивается через `[filament_switch_sensor]`, команды `SET_FILAMENT_SENSOR` |

**Важно:** Klipper позволяет эмулировать почти любую отсутствующую команду через макросы, поэтому многие синтаксические различия нивелируются настройками пользователя.

---

## 8. Типичные ошибки и отладка

- **Не указан `;`** – строка будет выполнена, даже если вы хотели её отключить.
- **Регистр адресов** – хотя `x` часто работает, используйте `X` для надёжности.
- **Неправильный разделитель** – `10,5` вместо `10.5` вызовет ошибку.
- **Пробел в команде** – `G 1` не распознается.
- **Конфликт модальных состояний** – если файл начался с `G91`, а слайсер ожидает `G90`, координаты будут восприняты как относительные и приведут к аварии. Всегда задавайте `G90` в стартовом коде.
- **Скорость выше лимита** – заданная `F` будет ограничена максимальной скоростью оси, что может привести к недокрутке экструзии.
- **Забытый `M400`** – при изменении тока, шагов/мм или других параметров без ожидания очереди можно получить сбой во время движения.

**Совет:** проверяйте незнакомые последовательности, отправляя их в терминал по одной строке и наблюдая за ответами (`ok`, сообщения об ошибках).

# Синтаксис и архитектура G-кода для 3D-печати

В этой статье подробно рассматривается формальный язык G-кода, его расширения в Marlin и Klipper, а также внутренняя логика интерпретации команды прошивкой. Знание этих основ необходимо для чтения, написания и отладки управляющих программ.

---

## 1. Алфавит и лексические элементы

Строка G-кода состоит из следующих элементов:

### 1.1. Буквенные адреса
Латинская буква, за которой следует числовое значение. Адрес определяет назначение числа. Основные адреса перечислены в таблице.

| Адрес | Назначение |
|-------|------------|
| `G` | Подготовительная (основная) команда: движение, единицы, системы координат |
| `M` | Вспомогательная команда: нагрев, вентиляторы, настройки |
| `T` | Выбор инструмента (экструдера) |
| `N` | Номер строки (для проверки целостности) |
| `O` | Номер программы / подпрограммы (традиционно для ЧПУ, в 3D-печати — редко) |
| `X`, `Y`, `Z` | Координаты осей, мм |
| `E` | Экструзия, мм |
| `F` | Скорость подачи, мм/мин |
| `S` | Температура, скорость вентилятора, яркость и т.д. |
| `P` | Время, номер инструмента, индекс и пр. |
| `R` | Радиус дуги, температура ожидания |
| `I`, `J`, `K` | Центр дуги (относительно начальной точки) |
| `*` | Контрольная сумма строки |

Каждый адрес образует «слово». В одной строке могут присутствовать несколько слов, разделённых пробелами (пробелы не обязательны, но допустимы).

### 1.2. Комментарии
Начинаются с `;` (точка с запятой) — всё до конца строки игнорируется. Klipper дополнительно поддерживает `#` как комментарий (стиль Python), но для совместимости со слайсерами рекомендуется `;`.

### 1.3. Расширения Klipper
Klipper вводит несколько дополнительных лексических форм:

- **Команды с восклицательным знаком `!`** — аварийные/немедленные команды. Пример: `!FIRMWARE_RESTART`. Обрабатываются вне очереди движений.
- **Команды с вопросительным знаком `?`** — запросы состояния (аналог M-кодов, но в стиле Klipper). Например, `?` (одиночный знак вопроса) запрашивает текущую позицию.
- **Именованные команды** — слова без числового суффикса, состоящие из букв и символов подчёркивания. Примеры: `SET_GCODE_OFFSET`, `BED_MESH_CALIBRATE`, `SAVE_CONFIG`. Они являются частью протокола Klipper и не вписываются в стандарт G/M.
- **Макросы** — пользовательские блоки, определяемые в конфигурации как `[gcode_macro ИМЯ]`. Могут иметь любое имя, в том числе переопределять существующие G/M-коды.

---

## 2. Структура строки

Полная форма строки с контрольной суммой (используется при передаче по ненадёжным каналам):

```
N<номер> <команда> ... <аргументы> *<чексумма>
```

**Пример:**
```
N123 G1 X10 Y20 *119
```

- `N123` — номер строки. Прошивка ожидает номера по порядку; при несовпадении запрашивает повторную отправку (только в режиме проверки).
- `*119` — контрольная сумма. Вычисляется как XOR всех байт между `N` и `*` (не включая сами `N` и `*`). Если чексумма не совпадает, команда отклоняется.

При печати с SD-карты или из слайсера номера строк и контрольные суммы обычно **не используются**. Они активируются хостом (например, OctoPrint) при включённой опции «проверка строк». В файлах `.gcode` вы увидите строки без `N` и `*`.

### 2.1. Классический номер программы (O-слово)
В стандарте RS-274 (исторический G-код для станков) адрес `O` задаёт номер программы или подпрограммы. Например: `O1000` — начало подпрограммы 1000, вызов через `M98 P1000`. В **3D-печати подпрограммы практически не применяются**:
- Marlin не поддерживает `O`-слова и `M98`/`M99`.
- Klipper также не имеет встроенной поддержки, но логику подпрограмм можно реализовать макросами с параметрами.

Тем не менее, в некоторых прошивках (Smoothieware, старые версии Marlin с патчами) встречается ограниченная поддержка. В любительской печати это экзотика, и слайсеры не генерируют `O`-коды.

---

## 3. Типы команд и их выполнение

### 3.1. Стандартные G- и M-команды
Формат: буква + целое число (иногда с десятичной частью, например `G38.2`). Регистр не важен, но заглавные — правило хорошего тона. Пробел между буквой и числом недопустим.

**Примеры:**
```
G1 X10 Y20 E5 F1500
M104 S210 T0
```

### 3.2. Команда выбора инструмента T
`T0`, `T1` и т.д. Формально это отдельный тип команды, но в Marlin и Klipper она обрабатывается как полноценная смена экструдера. В Marlin может запускать макрос смены инструмента; в Klipper часто реализуется через макрос `ACTIVATE_EXTRUDER`.

### 3.3. Расширенные команды Klipper
Klipper использует собственный протокол, основанный на JSON, но для совместимости принимает текстовые команды. Расширенные команды имеют произвольный строковый идентификатор:

- `SET_GCODE_OFFSET Z_ADJUST=0.05`
- `QUERY_ENDSTOPS`
- `BED_MESH_PROFILE LOAD=default`

Они не являются G-кодом в традиционном понимании, но могут вызываться из того же потока управления. Такие команды могут иметь параметры в формате `ИМЯ=ЗНАЧЕНИЕ`, что нехарактерно для классического G-кода.

### 3.4. Немедленные команды Klipper
Начинаются с `!` и обрабатываются вне очереди, даже если буфер движений заполнен:
- `!RESTART` — перезагрузка прошивки на плате.
- `!FIRMWARE_RESTART` — перезагрузка хоста Klipper.
- `!QUERY_ENDSTOPS` — мгновенный запрос концевиков.

### 3.5. Запросы состояния
Одиночный знак `?` (в Klipper) возвращает краткий статус: позицию, температуру, состояние. Также используется `?` в начале команды для запросов, например `?extruder`.

### 3.6. Модальные и немодальные команды
Эта классификация применима и к расширенным командам:

- **Модальные**: `G90`/`G91` (режим координат), `G21` (единицы), `M82`/`M83` (экструзия), `SET_VELOCITY_LIMIT` (Klipper, действует до следующего изменения).
- **Немодальные**: `G28`, `M109`, `M400`, `SET_GCODE_OFFSET` (однократное действие).

---

## 4. Обработка команды прошивкой

### 4.1. Marlin
Marlin — монолитная прошивка на C++. Обработка G-кода происходит в основном цикле:

1. Чтение байта из последовательного порта или SD-карты.
2. Построение строки до символа `\n` или `\r\n`.
3. Парсинг: извлечение буквенных адресов и значений, заполнение внутренней структуры.
4. Если команда — движение (`G0`/`G1`/`G2`/`G3`), она помещается в **буфер планировщика движений** (размер по умолчанию 16). Планировщик непрерывно вычисляет траекторию и шаговые импульсы с учётом ускорений, скоростей и рывков.
5. Немодальные команды (нагрев, пауза) обрабатываются немедленно, но могут ожидать опустошения буфера движений, если требуют синхронизации (например, `M109` ожидает завершения перемещений и нагрева).
6. После выполнения отправляется `ok` (если включён режим подтверждений).

**Важно:** Marlin не позволяет переопределять встроенные команды без перекомпиляции. Любой нераспознанный G- или M-код вызывает предупреждение.

### 4.2. Klipper
Klipper разделён на две части:

- **Хост (klippy)** — программа на Python, работающая на Raspberry Pi или подобном компьютере. Она принимает G-код через виртуальный последовательный порт или API, парсит и выполняет высокоуровневую логику.
- **Микроконтроллер (mcu)** — прошивка на плате принтера, которая только получает команды шаговых импульсов и передаёт данные с датчиков.

Процесс обработки команды:

1. Хост читает строку из входа (серийный порт, сокет, файл виртуального SD).
2. Парсер определяет тип команды:
   - Стандартный G/M/T-код обрабатывается модулем `gcode_handlers`.
   - Расширенные команды (`SET_...`, `QUERY_...`) обрабатываются соответствующими модулями (например, `toolhead`, `heater`, `bed_mesh`).
   - Макросы (`[gcode_macro]`) разворачиваются в шаблоне Jinja2 и затем рекурсивно выполняются.
   - Немедленные команды (`!...`) передаются напрямую в обход очереди.
3. Если команда порождает движение, хост генерирует траекторию с учётом кинематики и помещает её в **очередь движений** (практически без ограничений по размеру). Планировщик на хосте вычисляет временные интервалы и отправляет на mcu поток шаговых импульсов.
4. Хост может параллельно обслуживать несколько команд (например, нагрев и движение), синхронизируя их через систему событий.

**Главное отличие:** в Klipper любая команда может быть переопределена или создана заново макросом без изменения исходного кода. Это даёт беспрецедентную гибкость, но требует понимания синтаксиса Jinja2 для сложных сценариев.

### 4.3. Буферизация и синхронизация
В обеих прошивках действует буферизация движений. Команда `M400` ожидает, пока все запланированные движения не завершатся. Она необходима перед изменением параметров, которые влияют на будущие перемещения (например, `M92`, `M350`). Без `M400` изменение может примениться к движениям, уже находящимся в очереди, что приведёт к непредсказуемому поведению.

Команды реального времени (`M112`, `M410`, `!RESTART`) не ждут буфера и прерывают текущую операцию.

## 5. Программная реализация: от строки к действию

### 5.1. Парсинг строки
Рассмотрим типичный алгоритм парсинга в Marlin (упрощённо):

```
Пока есть символы в строке:
  Прочитать букву (адрес).
  Прочитать число (целое или дробное).
  Сохранить в соответствующую переменную команды (X, Y, Z, E, F, S и т.д.).
  Пропустить пробелы.
```

В Klipper парсер более сложный, так как поддерживает ключевые слова с параметрами: `SET_GCODE_OFFSET Z=0.1 MOVE=1`. Здесь используется разбор по токенам: сначала читается команда, затем список `КЛЮЧ=ЗНАЧЕНИЕ`.

### 5.2. Диспетчеризация команды
После парсинга вызывается функция-обработчик, ассоциированная с кодом команды. В Marlin это огромный `switch/case` по G- и M-номерам. В Klipper — реестр команд, который можно расширять модулями и макросами.

### 5.3. Генерация движений
Команды движения (`G0`, `G1`, `G2`, `G3`) передают целевую позицию и скорость в планировщик. Планировщик разбивает прямую (или дугу) на множество маленьких сегментов, для каждого вычисляет время шага и генерирует импульсы. В Marlin это делается на mcu в реальном времени. В Klippler — на хосте, а mcu лишь получает готовый план шагов.

### 5.4. Обработка макросов (Klipper)
Макросы пишутся на Jinja2 с доступом к переменным принтера. Например:

```
[gcode_macro M600]
gcode:
    SAVE_GCODE_STATE NAME=M600_state
    G91
    G1 Z10 F600
    G90
    G1 X0 Y0 F6000
    M109 S200
    PAUSE
    RESTORE_GCODE_STATE NAME=M600_state
```

При вызове `M600` хост разворачивает шаблон, выполняет получившиеся команды. Макросы могут содержать условные операторы и циклы, что превращает G-код в полноценный скриптовый язык.

## 6. Типичные ошибки и нюансы синтаксиса

- **Регистр адресов:** `g1` обычно работает, но `X` и `x` могут различаться в редких случаях. Рекомендуется всегда использовать верхний регистр.
- **Разделитель дробной части:** только точка `10.5`, запятая `10,5` вызовет ошибку парсинга.
- **Пробел после буквы:** `G 1` невалидно, правильно `G1`.
- **Неизвестные команды:** в Marlin — предупреждение и пропуск, в Klipper — ошибка (если не определён макрос).
- **Дублирование адресов:** `G1 X10 X20` — поведение не определено (обычно используется последнее значение, но лучше избегать).
- **Отсутствие обязательных параметров:** для дуг (`G2`/`G3`) необходимо указать либо `R`, либо `I`/`J`. Иначе — ошибка.
- **Смешение модальностей:** если слайсер выдаёт координаты в абсолютном режиме (`G90`), а стартовый код по ошибке устанавливает `G91`, принтер уедет в непредсказуемом направлении. Поэтому стартовый код всегда должен явно задавать `G90` и `M82`/`M83`.
